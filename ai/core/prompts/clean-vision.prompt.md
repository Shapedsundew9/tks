# Clean Vision

Use the `.shared/docs/guides/vision-style-guide.md` as a reference to clean and standardize the specified vision document. Ensure that all sections, formatting, and content adhere to the guidelines outlined in the style guide.

## Information Preservation

**INFORMATION MUST NOT BE LOST DURING THIS PROCESS.** If content, requirements, or specifications need to be adjusted to comply with the style guide, the additional detail and context shall be moved to the supplied strategic planning backlog document. If you are unsure, ask the user.

### MVD Elaboration Boundary

MVD (Minimum Viable Demonstration) descriptions should retain enough specificity to describe **what** must be demonstrated, including approximate scales, directional targets, and conditional structure. Only move precise numerical acceptance criteria, exact sample sizes, and detailed test rig protocols to the backlog.

### No Fabricated Content

Do **not** invent, fabricate, or add content that does not exist in the original document. If the style guide implies a section that the original does not address (e.g., scope boundaries, strategic leverage), add the section heading with a placeholder indicating the gap for the author to fill—do not generate the content.

### Over-Condensation

When simplifying dense passages, ensure the simplified version preserves the same logical assertions and conditional structure. If in doubt about whether a detail is "too specific" for the vision, keep it and flag it for review rather than removing it.

## Change Manifest

Before making changes, produce a numbered change manifest listing every planned modification: what is being moved, what is being restructured, what is being reworded, and what sections are being created. Present this manifest, and the `.shared/docs/guides/vision-style-guide.md` as a reference, for review by a reviewing agent before editing.

## Post-Edit Audit

After restructuring, audit the document for content that appears in multiple sections due to reorganization. Consolidate to a single canonical location and add a brief forward reference from secondary locations (e.g., "per §3") rather than repeating content.
